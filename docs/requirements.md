# pimu-note 要件定義書

- **版**: v0.8
- **作成日**: 2026-09-09
- **更新日**: 2026-09-11（F-307・F-505 追加、アイコンの色を一段明るく）
- **想定リリース**: v1（社内配布）

---

## 1. 背景と目的

Raycast の Note 機能は「起動が速く、Markdown で書け、書式が整って見える」点で日常のメモとして優秀だが、
**コピーすると書式付きテキストになってしまい、Markdown のソースをそのまま貼りたい場面で使いづらい**。

本アプリは、その体験を再現しつつ、**コピー時に Markdown のソース（`#` や `**` を含むプレーンテキスト）を
確実に取り出せる**ことを最大の価値とする、社内向け macOS デスクトップアプリである。

### 解決する課題

| 課題 | 本アプリでの解決 |
|---|---|
| Raycast Note からコピーすると Markdown 記法が消える | クリップボードにプレーン Markdown を必ず含める |
| メール下書きなど、書式付きで貼りたい場面もある | 書式付き HTML も同時に入れ、貼り先の操作で選ばせる |
| 貼り付け時に色・フォントが意図せず持ち込まれる | HTML は構造タグのみで生成し、スタイルを一切載せない |

## 2. スコープ

### 2.1 対象

- **プラットフォーム**: macOS のみ、**Apple Silicon（arm64）専用**。Intel Mac は対象外
- **利用者**: 社内メンバー **4名**
- **配布形態**: private リポジトリからの社内配布（オープンソース化はしない）

### 2.2 v1 に含むもの

- 複数ノートの作成・編集・切替・削除（左：ノート一覧／右：エディタ の2ペイン構成）
- Markdown シンタックスハイライト付きエディタ
- 入力支援（リスト自動継続、インデント、太字/斜体ショートカット）
- デュアルフォーマットコピー（プレーン Markdown ＋ スタイル無し HTML）
- ローカル `.md` ファイル保存、保存先フォルダの変更
- グローバルホットキーによる呼び出し
- ダークモード対応
- `.md` ファイルのドラッグ&ドロップ取込み・書き出し

### 2.3 v1 に含まないもの（v2 以降）

- **全文検索**（ノート数が増えてから対応）
- フォルダ / タグによる整理
- 自社サーバによるクラウド同期・ノート共有
- Windows 対応
- Developer ID 署名・公証（Notarization）
- 自動アップデート

## 3. 機能要件

### 3.1 ノート管理

| ID | 要件 |
|---|---|
| F-101 | 左ペインにノート一覧を表示する。各行はタイトルと更新日時を表示する |
| F-102 | ノートのタイトルは本文1行目から自動生成する（`# ` 等の記号は除去して表示） |
| F-103 | 新規ノートを作成できる（`Cmd+N`） |
| F-104 | ノートを削除できる。削除前に確認する |
| F-105 | ノート一覧は更新日時の降順で並べる |
| F-106 | 編集内容は自動保存する（デバウンス、目安 500ms） |

### 3.2 エディタ

| ID | 要件 |
|---|---|
| F-201 | Markdown を**シンタックスハイライトのみ**で表示する。文字サイズ・行の高さは変更しない |
| F-202 | `#` `**` `-` 等の記法記号は常に表示したままにする（インラインプレビューはしない） |
| F-203 | ハイライト対象：見出し / 強調・斜体 / リスト記号 / コード（インライン・ブロック）/ リンク / 引用 |
| F-204 | `- ` の行で Enter → 次行に `- ` を自動挿入する |
| F-205 | 内容が空のリスト項目で Enter → リスト記号を解除する |
| F-206 | `1. ` の番号リストは自動採番する |
| F-207 | `- [ ] ` チェックボックスも同様に継続する |
| F-208 | Tab / Shift+Tab でリストのインデントを上げ下げする |
| F-209 | 選択して `Cmd+B` → `**太字**`、`Cmd+I` → `*斜体*` で囲む |

### 3.3 コピー（本アプリの中核）

| ID | 要件 |
|---|---|
| F-301 | `Cmd+C` は、クリップボードに **plain text（Markdown ソース）** と **HTML** の両方を書き込む |
| F-302 | plain text は編集中のソースを**一切加工せず**そのまま入れる |
| F-303 | HTML は `h1`〜`h6` / `strong` / `em` / `ul` / `ol` / `li` / `code` / `pre` / `blockquote` / `a` の**構造タグのみ**で生成する |
| F-304 | HTML に `style` 属性・`class`・色・フォント・サイズ指定を**一切含めない** |
| F-305 | `Cmd+Shift+C` は plain text のみをクリップボードに書き込む（書式付き貼付けを完全に防ぐ保険） |
| F-306 | 設定で「常にプレーンのみコピーする」に切り替えられる |
| F-307 | コピーの経路（エディタ内の `Cmd+C`、編集エリア外からの全選択コピーなど）を問わず、ブラウザが見た目を焼き込んだ HTML を載せない。アプリ全体の copy を横取りして自前の HTML に差し替える |

**期待される貼り付け挙動（貼り先アプリ側の操作）**

| 貼り先での操作 | 貼られる内容 |
|---|---|
| `Cmd+V`（Gmail / Slack / Google Docs / Notion 等） | 書式付き |
| `Cmd+Shift+V`（同上） | Markdown ソース |
| `Cmd+V`（VSCode / GitHub 入力欄 / ターミナル等） | Markdown ソース（自動的に plain が選ばれる） |

> 注：`Cmd+V` / `Cmd+Shift+V` の挙動は貼り先アプリが決めるものであり、本アプリが制御するのは
> 「クリップボードに何を入れるか」のみ。`Cmd+Shift+V` 非対応のアプリ向けに F-305 を用意する。

### 3.4 保存・ファイル連携

| ID | 要件 |
|---|---|
| F-401 | 1ノート = 1つの `.md` ファイルとしてローカルに保存する |
| F-402 | 保存先フォルダを設定画面から変更できる。デフォルトは `~/Documents/pimu-note/` |
| F-403 | iCloud Drive / Google Drive 等のフォルダを指定することで、端末間同期を実現できる |
| F-404 | 外部で `.md` が変更された場合、ファイル監視により一覧・エディタへ反映する |
| F-405 | `.md` ファイルをウィンドウにドラッグ&ドロップすると、ノートとして取り込む |
| F-406 | ノートを `.md` ファイルとして任意の場所に書き出せる |

### 3.5 起動・ウィンドウ

| ID | 要件 |
|---|---|
| F-501 | グローバルホットキーでウィンドウを表示 / 非表示できる。**既定値は `Cmd+Option+N`** |
| F-501a | ホットキーは設定画面から**任意の組み合わせに変更できる**（キー入力で直接記録する方式） |
| F-501b | 他アプリや macOS が既に使っている組み合わせは登録できないため、その旨をユーザーに提示する |
| F-501c | ホットキー押下時は**可視状態とフォーカス状態を分けて3通りで判定**する。①隠れている→表示して前面へ ②見えているが背面→前面に出すだけ（隠さない） ③すでに最前面→しまう |
| F-503 | ウィンドウを閉じてもプロセスは常駐し、ホットキーで即座に復帰できる |
| F-503a | 常駐中に Dock アイコンをクリックしたらウィンドウを再表示する |
| F-504 | 前回のウィンドウ位置・サイズ・開いていたノートを復元する |
| F-505 | 「常に最前面」をツールバーのピン留めで切り替えられる。状態は保存し、次回起動時に復元する。既定はオフ |

**F-501b の実装上の限界（Phase 4 で判明・2026-09-10）**

「登録に失敗したら知らせる」は、当初想定していたようには実現できない。

macOS では、他アプリや OS が既に押さえている組み合わせは**そもそもアプリまでキーが届かない**。
相手が先に反応してしまうため、登録の成否以前に「押された」ことすら検知できない。
また `RegisterEventHotKey` は、システムが使っている組み合わせでも登録自体は
成功してしまうことがあり、エラーとして拾えない。

そこで次の 2 段構えで代替する。

1. ホットキーの記録中にウィンドウがフォーカスを失ったら、
   「ほかのアプリが先に反応した」と判断して知らせる
2. macOS が使っていることが多い組み合わせ（Spotlight、スクリーンショット、
   Mission Control など）は、選ばれた時点で注意を出す。
   システム設定で当該機能を切っていれば使えるため、禁止ではなく警告に留める

**権限について（Phase 0 で実機検証済み・2026-09-10）**

グローバルホットキーは Carbon の `RegisterEventHotKey` 経由で登録されるため、
**アクセシビリティ権限は不要**。実機で権限ダイアログが出ないことを確認した。
当初あった「必要に応じてアクセシビリティ権限を要求する」要件は削除した。

### 3.7 アプリ名・アイコン

| ID | 要件 |
|---|---|
| F-701 | アプリ名は **pimu-note** とする |
| F-702 | アイコンは絵文字 **🗒️（spiral notepad）** を、**水色のグラデーション背景**の上に配置したものとする |
| F-702a | ベースカラーは **`#3BACED`**（`hsl(202, 83%, 58%)`）とする。当初は `#1281C0` だったが、配布後に「暗く感じる」との声があり一段明るくした（v0.1.0 を作り直して反映） |
| F-702b | 背景は縦方向グラデーション **`#60BCF0` → `#169DE9`**（`linear-gradient(180deg, ...)`）とする。ベースカラーが上下の中間に位置する配分 |
| F-702c | グラデーションは色相 202°・彩度 83% を固定し、明度のみを振る（混色しない） |
| F-703 | 背景は macOS の角丸スクエア（squircle）に合わせる。元画像には余白を付けず角丸いっぱいに描く（macOS 26 は従来形式のアイコンをシステム側で縮めて置くため、余白があると二重に縮んで小さく見える） |
| F-704 | `.icns` として 16/32/128/256/512pt の @1x・@2x を全て用意する |

**絵柄の出典について**

Apple Color Emoji のグリフを画像として書き出してアプリに埋め込むのは、Apple のフォント資産の
再配布にあたるためライセンス上はグレーである。社内4名への限定配布であれば実務上の問題は生じないが、
懸念がある場合は **Twemoji（CC BY 4.0・商用利用可）** の同一絵柄に差し替える。
Twemoji を採用する場合は、README に帰属表示を記載する。

## 4. 非機能要件

| 区分 | 要件 |
|---|---|
| 起動速度 | ホットキー押下からウィンドウ表示まで 200ms 以内 |
| 編集追従 | 入力からハイライト反映まで体感遅延なし（1000行程度のノートで） |
| メモリ | 常駐時 150MB 以内を目安 |
| アプリサイズ | 30MB 以内を目安 |
| データ保護 | ノートは**一切外部送信しない**。ネットワーク通信は行わない |
| 対応OS | macOS 14 (Sonoma) 以降 |

## 5. 技術構成

| 項目 | 選定 |
|---|---|
| フレームワーク | **Tauri v2**（Rust ＋ Web フロントエンド） |
| フロントエンド | React ＋ TypeScript |
| エディタ | CodeMirror 6（`@codemirror/lang-markdown`） |
| Markdown → HTML | `markdown-it`（生成後に許可タグのホワイトリストでサニタイズ） |
| 保存 | ローカル `.md` ファイル（Tauri fs API） |
| ビルド | GitHub Actions |

### 選定理由

- **Tauri**：常駐アプリのためメモリ・起動速度が重要。Electron 比でサイズ約1/10、メモリも大幅に小さい
- **CodeMirror 6**：Markdown のシンタックスハイライトと入力支援を標準機能でほぼ賄える。行の高さを変えない
  ハイライト（要件 F-201）が素直に実装できる

**配布人数は4名のため、当面 Apple Developer Program（年 $99）は取得しない。**
Gatekeeper の初回手順は4名に一度説明すれば済み、年 $99 に見合わない。
将来、配布人数が大きく増えた場合、または社外への配布が発生した場合に再検討する。
